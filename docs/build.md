# Сборка внешней обработки

Для использования готового выпуска скачайте EPF из Releases. Сборка нужна при изменении исходников.

Проверено на Windows, PowerShell 7.6 и платформе **1С:Предприятие 8.3.27.2074**. Нужны установленная платформа с Конфигуратором и доступная файловая тестовая база с правом запуска Конфигуратора. Платформа и база в репозиторий не включены.

## Порядок действий

1. Откройте PowerShell 7 в корне репозитория.
2. Выполните `npm test` (проверенная версия Node.js — 24.21.0).
3. Запустите скрипт с реальными путями своей платформы и тестовой базы:

```powershell
& .\scripts\Build.ps1 `
    -PlatformExe 'C:\Program Files\1cv8\8.3.27.2074\bin\1cv8.exe' `
    -InfoBasePath 'C:\Bases\Test' `
    -UserName 'Администратор'
```

Пути в примере нужно заменить. При необходимости добавьте `-Password (Read-Host 'Пароль базы' -AsSecureString)` в ту же команду. Для базы без аутентификации параметр `-UserName` можно опустить.

Результат по умолчанию: `dist/scheduler4000.epf`, рядом журнал Конфигуратора. Скрипт выводит SHA-256. Если файл уже существует, выберите новое имя через `-OutputFile` или перенесите прежний результат: скрипт не перезаписывает готовую сборку.

Скрипт вызывает только `DESIGNER /LoadExternalDataProcessorOrReportFromFiles`: он упаковывает внешнюю обработку из `EPF/scheduler4000.xml`, не загружает и не обновляет конфигурацию базы. Сообщение об успешной сборке означает создание EPF, а не полный анализ BSL или приемку поведения. После изменений нужны соответствующие проверки в 1С.

Для клиент-серверной базы можно использовать штатную команду Конфигуратора с `/S` вместо `/F`; включенный скрипт предназначен для файловой тестовой базы.
